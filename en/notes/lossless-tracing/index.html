What does a lossless trace need to preserve?

A smaller file is the outcome. Exact interpretation of every record is the constraint.

DQR-Happy2026-11-154 min read
On this page
  1. Start with record semantics
  2. Exploit references without discarding precision
  3. There is a system around the codec
  4. Observed records have interpretation limits

Start with record semantics

Lossless is meaningful only within a stated capture scope. Specify the kernels, execution units, fields, precision, order, and ownership being recorded. Exact record-by-record recovery then becomes a concrete requirement. Narrowing the scope or replacing records with aggregate statistics changes the question.

Exploit references without discarding precision

Records in an execution context can share useful reference information. ERETrace uses SM / CTA references to reduce redundant representations of original fields. References and residuals must recover the original values. Checked raw fallback preserves complete records when narrow-field range conditions fail. The representation changes; timestamp precision does not.

There is a system around the codec

A better compression ratio does not guarantee lower collection latency. Reference construction, encoding, buffering, D2H transfers, and output all have costs and may overlap. Bounded buffers, fallback paths, and the final drain matter when turning a representation benefit into a workflow benefit.

Observed records have interpretation limits

Warp timing and SM attribution support execution analysis, but do not represent all physical memory traffic. Repeated addresses do not directly imply cache misses, and explicit copy bytes are not kernel DRAM traffic. Conclusions should follow the fields the probe actually records; hardware-counter questions require the corresponding diagnostic tools.
