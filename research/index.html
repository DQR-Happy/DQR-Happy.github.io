Execution-Reference Encoding and Recovery-Aware Collection for GPU Profiling

School of Computer Science and Information Security, Guilin University of Electronic Technology

Fine-grained GPU tracing produces large volumes of records, and collection overhead can substantially perturb the workload being observed. ERETrace combines execution-reference encoding with recovery-aware collection to reduce complete-request collection latency and output size while preserving record semantics.

Project site↗GitHub↗v1.0.0↗

Three parts of the method

01 / Execution references

Use SM / CTA references to reduce redundant representation, with narrow fields under checked range conditions and the information needed for exact recovery.

02 / Checked fallback

Retain raw records when encoding acceptance conditions fail. Field values, precision, order, and execution attribution remain recoverable; dedicated correctness runs verify losslessness.

03 / Bounded collection

Integrate reference encoding with a bounded asynchronous collection pipeline, coordinating encoding, D2H transfers, and output to evaluate the complete request cost.

Implementation & reproduction

Execution environment

Linux / CUDA, built on Neutrino programmable probing. The public artifact includes build instructions, patches, workload entry points, and configurations.

Record semantics

Default fine-grained records include per-warp start, elapsed, and SM ID, with execution attribution. Records must be exactly recoverable.

Engineering scope

The main evaluation, NVBit / XTrace integrations, and capacity prototype have separate configurations and support scopes, documented in the artifact.

Tracing benefits depend on semantics, time, and space together. Smaller files do not imply faster kernels, and collector performance is distinct from native model inference performance.
